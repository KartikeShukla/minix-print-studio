# MCP Integrations

MiniX Print Studio exposes local agent tools through a stdio MCP shim. MCP clients
talk to the daemon over localhost and never open BLE connections directly.

## Runtime Handoff

The Electron app writes a runtime handoff under app user data:

- `runtime/runtime.json`: daemon base URL, PID, mock flag, and token-file path.
- `runtime/token`: bearer token used by the local daemon.

Committed MCP configs must stay token-free. Runtime paths are generated by the desktop
app or supplied explicitly for local development.

## Supported Targets

- Codex
- Claude Desktop and Claude Code
- OpenCode
- Generic stdio MCP clients

The renderer's Agent Integrations panel previews config snippets, installs supported
targets with backup manifests, tests prerequisites, and can uninstall only the managed
MiniX entry.

## Security Boundary

- MCP tools are semantic: render preview, preview document compatibility, print
  note, daemon status, redacted job status, and supported profile listing.
- MCP tools do not expose approval tokens.
- `render_preview` is the spec-facing preview tool; `preview_document` remains
  available as a compatibility alias.
- `get_job_status` returns daemon job state, completion confidence, progress,
  and safe user actions without raw raster or segment payloads.
- `list_supported_profiles` returns safe profile summaries without BLE UUIDs,
  read-only probe commands, or printer protocol payload details.
- Print-related MCP responses include daemon preview safety data when available.
- `print_note` returns an explicit policy decision. Without a reviewed opt-in
  gate, direct printing remains blocked by the default agent policy. With a
  reviewed `agent_direct_user_opt_in` gate, the tool may enter the
  approval-required runtime path, but it still does not dispatch printer bytes or
  allow unattended printing.
- MCP tools do not accept raw BLE commands.
- The daemon remains the only production owner of printer transport.
